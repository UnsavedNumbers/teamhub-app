Cloudflare: Testing vs Production — Developer Guide

This document explains how the YouthSports.team web app uses Cloudflare for hosting and how to set up separate testing and production environments.

1. Current Setup

The app is deployed on Cloudflare Pages (Git integration). There is no wrangler.toml in the repo; configuration is done in the Cloudflare dashboard.

  • Routing: public/_redirects sends all routes (/portal/*, /admin/*, /*) to index.html for client-side routing (React Router).
  • Auth: Supabase is used with PKCE; the app reads VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY at build time (see src/lib/supabase.ts).

To have testing vs production, you need to decide:

  1. Which Cloudflare deployments count as “production” vs “testing.”
  2. Which Supabase project (and keys) each environment uses.

2. Easiest Approach: One Project, Two Environments

Use a single Cloudflare Pages project and rely on built-in Production and Preview deployments.

EnvironmentTriggerURL
Production Pushes (or merges) to the branch you set as “Production branch” in Pages (e.g. main) https://<project>.pages.dev or your custom domain
Testing (Preview) Pushes to any other branch, or opening a PR https://<commit-hash>.<project>.pages.dev or PR preview URL

No code changes are required. You only configure the production branch and environment variables in the Cloudflare dashboard.

Stable testing URL: If you use a long-lived branch (e.g. staging or develop), each new push updates that branch’s preview deployment. You can bookmark the latest preview URL for that branch from the Cloudflare Pages deployment list, or use a second Pages project (see section 4) for a fixed subdomain.

3. Environment Variables (Supabase)

The app expects these at build time:

  • VITE_SUPABASE_URL
  • VITE_SUPABASE_ANON_KEY

To point production at your production Supabase project and testing at a separate Supabase project:

  1. Create two Supabase projects (e.g. “YouthSports Production” and “YouthSports Staging”) and get each project’s URL and anon key.
  2. In Cloudflare: open your Pages project → Settings → Environment variables.
  3. Add the same variable names for both environments:
    • Production: VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY = production Supabase values.
    • Preview (or “Staging” if you add a custom environment): same names, but use the testing Supabase URL and anon key.

Cloudflare builds from the production branch use Production variables; all other builds (other branches, PRs) use Preview variables. So production deployments talk to production Supabase, and preview/testing deployments talk to testing Supabase.

Important: Changing environment variables in the dashboard only affects new builds. Redeploy (e.g. re-run the build or push a small commit) after changing variables.

4. Optional: Two Cloudflare Pages Projects

If you want two clearly separate sites with stable URLs (e.g. production on app.youthsports.team and testing on staging.youthsports.team):

  1. Create a second Pages project in the same Cloudflare account (e.g. “youthsports-web-staging”).
  2. Connect the same Git repo to both projects.
  3. Configure each project:
    ProjectProduction branchCustom domainEnv vars
    Production main app.youthsports.team Production Supabase
    Staging / Testing staging or develop staging.youthsports.team Testing Supabase

Same repo, different branch and different env vars per project. More to maintain, but gives you two fixed URLs and clear separation.

5. Quick Reference

GoalAction
Production buildsSet “Production branch” (e.g. main) in Pages → Settings → Builds & deployments.
Testing buildsPush to another branch or open a PR; Cloudflare creates a Preview deployment.
Prod uses prod SupabaseSet VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY under Production env in Pages.
Testing uses staging SupabaseSet the same variable names under Preview (or Staging) with the staging Supabase values.
Stable testing URLUse a dedicated branch (e.g. staging) and bookmark its preview URL, or add a second Pages project with that branch as “production” and a subdomain.

No changes to _redirects or app code are required for the basic “one project, production + preview” setup; the only requirement is configuring the branch and environment variables in the Cloudflare Pages dashboard.
