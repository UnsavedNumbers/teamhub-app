================================================================================
WORKFLOWS & USER FLOWS
================================================================================

┌─────────────────────────────────────────────────────────────────────────┐
│  FEE CREATION & ASSIGNMENT WORKFLOW                                      │
└─────────────────────────────────────────────────────────────────────────┘

    1. Admin navigates to /admin/payments/fees
    2. Clicks "Create Fee"
    3. Fills out fee form:
       - Basic info (title, type, amount)
       - Assignment settings (scope, season)
       - Payment options (partial, installments, etc.)
    4. Selects players (if scope = selected_players)
    5. Saves as draft or publishes immediately
    6. System creates fee_assignments for selected players
    7. If installments enabled, creates installment_schedules
    8. Parents receive notification (if published)
    9. Parents can view and pay fees

┌─────────────────────────────────────────────────────────────────────────┐
│  PAYMENT PROCESSING WORKFLOW                                             │
└─────────────────────────────────────────────────────────────────────────┘

    Online Payment:
    1. Parent views fee assignments
    2. Selects fees to pay (multi-select)
    3. Applies discount code (optional)
    4. Clicks "Pay Now"
    5. System creates checkout_session
    6. System creates charges for each fee
    7. Redirects to Stripe Checkout
    8. Parent completes payment
    9. Stripe webhook updates payment status
    10. System creates payment record
    11. System creates payment_allocations
    12. System updates fee_assignment balances
    13. System sends receipt to parent

    Offline Payment:
    1. Admin navigates to fee assignment
    2. Clicks "Record Offline Payment"
    3. Enters payment details (amount, method, reference)
    4. Saves payment
    5. System creates offline_payment record
    6. System creates offline_payment_allocations
    7. System updates fee_assignment balance
    8. System sends confirmation to parent

┌─────────────────────────────────────────────────────────────────────────┐
│  WAIVER/SCHOLARSHIP APPLICATION WORKFLOW                                 │
└─────────────────────────────────────────────────────────────────────────┘

    Waiver:
    1. Admin navigates to fee assignment
    2. Clicks "Apply Waiver"
    3. Enters waiver amount and reason
    4. Saves waiver
    5. System creates waiver record
    6. System creates negative charge (waiver_credit)
    7. System updates fee_assignment balance
    8. Parent receives notification

    Scholarship:
    1. Admin navigates to scholarship program
    2. Clicks "Create Award"
    3. Selects fee assignment
    4. Enters award amount
    5. Saves award
    6. System creates scholarship_award record
    7. System creates negative charge (scholarship_credit)
    8. System updates fee_assignment balance
    9. System updates program budget (if applicable)
    10. Parent receives notification

┌─────────────────────────────────────────────────────────────────────────┐
│  EVENT CREATION & ATTENDANCE WORKFLOW                                    │
└─────────────────────────────────────────────────────────────────────────┘

    1. Admin navigates to /admin/events
    2. Clicks "Create Event"
    3. Fills out event form (title, type, team, date/time, location)
    4. Optionally sets as recurring
    5. Saves event
    6. System creates event record
    7. System creates attendance records for all team members (if auto-create)
    8. Parents receive notification
    9. Parents can RSVP
    10. Admin can view/manage attendance
    11. Admin can export attendance report

┌─────────────────────────────────────────────────────────────────────────┐
│  TEAM ROSTER MANAGEMENT WORKFLOW                                        │
└─────────────────────────────────────────────────────────────────────────┘

    1. Admin navigates to team detail
    2. Goes to Roster tab
    3. Clicks "Add Player"
    4. Searches for existing child or creates new
    5. Selects season
    6. Saves membership
    7. System creates team_membership record
    8. Parent receives notification (if new child)
    9. Child appears in roster
    10. Admin can remove player (changes status to 'removed')

================================================================================
API ENDPOINTS & DATA FLOW
================================================================================

┌─────────────────────────────────────────────────────────────────────────┐
│  SUPABASE QUERIES (Examples)                                             │
└─────────────────────────────────────────────────────────────────────────┘

    Fees List:
    - Query: fees table
    - Filter: by organization_id, status, season_id
    - Join: seasons, organizations
    - Aggregate: count of fee_assignments

    Fee Assignments:
    - Query: fee_assignments table
    - Filter: by fee_id, child_id, parent_id, status
    - Join: fees, children, users (parents), organizations
    - Aggregate: balance_cents, paid_cents_total

    Payments:
    - Query: payments table
    - Filter: by organization_id, parent_id, status, date range
    - Join: checkout_sessions, payment_allocations, charges
    - Aggregate: total amount, platform fees

    Events:
    - Query: events table
    - Filter: by team_id, season_id, date range
    - Join: teams, seasons, attendance
    - Aggregate: attendance counts

================================================================================
NOTES & BEST PRACTICES
================================================================================

1. All monetary values stored in CENTS (integer)
2. All dates stored as TIMESTAMPTZ (timezone-aware)
3. All status changes should log to payment_events (audit trail)
4. RLS policies enforce data access at database level
5. Coaches see status only, never amounts (enforced by RLS)
6. Parents can only see their own data (enforced by RLS)
7. All financial operations should be atomic (transactions)
8. Stripe webhooks handle payment status updates
9. Offline payments still update balances and status
10. All exports should respect RLS policies
